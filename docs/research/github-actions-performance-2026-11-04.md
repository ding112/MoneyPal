# GitHub Actions 性能记录（2026-11-04）

## 范围与数据

使用 `gh run list --repo ding112/MoneyPal --limit 50` 获取历史，再通过 jobs API 读取每个作业的步骤时间。仓库只有 48 次可见运行：25 次 Test 成功、7 次 Test 失败、1 次 Test 取消、5 次 Release 成功、8 次 Release 失败、2 次工作流校验失败。其中 4 次没有可用的作业明细；其余共 44 个作业。[完整阶段表](actions-performance/baseline-2026-11-04.csv) 保留了缺失项。

阶段定义：队列为事件创建到作业开始；设置为作业开始到首个验收步骤开始，包括检出、工具链、安装、构建和运行时准备；执行为验收开始到作业结束，包括测试、打包和清理。Release 的执行阶段还含发布，CSV 另列 `publish_s`，不能把发布耗时当成测试耗时。API 时间精度为秒，不能从小样本推断稳定的亚秒差异。

## 第一轮修改

- PR 使用 PR 编号作为并发组，只保留最新运行。main 使用独立的 run_id 组；既不取消正在运行的提交，也不替换尚在排队的提交。只设置 `cancel-in-progress: false` 仍可能替换同组待运行任务，见 [官方并发规则](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)。
- Test 对 push 和 pull_request 加入 `**/*.md`、`docs/**` 路径过滤。混合变更完整执行。main 当前未受保护，唯一规则集处于 disabled，没有必需检查。以后启用必需检查前，必须按开发规范改为始终返回结果的变更检测与汇总检查，避免 [Pending 阻塞](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/skip-workflow-runs)。未改变仓库保护设置。
- Test 与 Release 都使用 setup-node 内置 npm 下载缓存；安装优先使用已有下载。审计和所有原有发布门禁保留。
- 只额外缓存可复用的 Python 运行时目录。缓存按 OS、架构、完整 Python 版本和运行时安装代码摘要隔离，不包含锁文件，不使用宽松恢复 key。恢复后仍运行 setup-runtime 和严格运行时检查。runner 安装时显式使用官方 PyPI。
- 集成测试文件从串行改为两个独立进程并行，文件内部不改。保留 103 个集成测试和 26 个发布测试、真实运行时要求、tarball 内容检查、隔离安装与入口加载。
- 完整构建用内容摘要确认输入与输出均未改变时才复用。输入覆盖 src、test、scripts、packages、清单、lockfile、tsconfig 和工具链版本；输出也校验内容和权限。源码删除或产物删除、损坏时重新清理构建。build:base 仍强制清理。

最长测试套件约 14 秒，采用现有 Node 运行器的两个进程先减少串行等待。多机器分片需要重复工具链、构建与运行时准备，还会增加队列和汇总开销；是否进一步分片以真实运行收益为准。

## GitHub 实测与第二轮

第一轮已推送并通过 [41768754245](https://github.com/ding112/MoneyPal/actions/runs/41768754245)。队列 3 秒、作业 34 秒；Python 缓存首次未命中，运行时准备 7 秒，完整验收 12 秒。103 + 26 个测试全通过，零跳过。npm 缓存命中，新的 Python 运行时缓存成功保存。

真实日志显示集成测试仍占 8.65 秒。本地使用相同 103 个用例尝试四进程，7.35 秒通过；因此第二轮将并发从 2 提到 4，保持每个测试文件内的行为不变。后续运行同时检查 Python 缓存能否命中，分别列出这两种收益。


第二轮 [41768949684](https://github.com/ding112/MoneyPal/actions/runs/41768949684) 同样通过。Python 缓存明确命中，准备步骤从 7 秒降至 1 秒；集成测试从 8.65 秒降至 5.66 秒。完整验收步骤为 9 秒。全部 103 个集成测试和 26 个发布测试通过，零跳过。[迭代数据](actions-performance/iterations-2026-11-04.csv) 使用相同阶段口径。

四进程的最终本地完整验收为 9.774 秒，比原先 23.207 秒减少 57.9%；连续第二次构建 0.120 秒，比原先 0.990 秒减少 87.9%。最终测试文件集合与执行次数逐项对照原版本，5 个快速测试文件、14 个集成测试文件、6 个发布测试文件均未减少。只更新现有工作流用例的并发及缓存契约，没有删除用例或弱化运行时要求。

实测缓存总量 15,254,100 字节，约 14.5 MiB：原有 npm 下载 8,461,149 字节，新增 Python 运行时 6,792,951 字节。未缓存 node_modules、dist 或第二份 pip 下载。PR 缓存按 GitHub 的 ref 范围隔离；合并后 main 首次建立自己的运行时缓存，不能把这次 PR 的缓存命中视为 main 已预热。

第二轮完整验收仅 9 秒，其中集成测试 5.66 秒。继续拆成多机器还需重复设置、构建并汇总检查；本次保留单个 Ubuntu 作业和四个测试进程，以控制总等待和重复工作。没有新增依赖或测试框架。发布工作流的缓存改动通过现有发布工作流测试；未创建 tag 或实际发布 npm，因而没有声称完成新的发布实测。
