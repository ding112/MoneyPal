# 以独立核心仓库收敛两端实现

2026-10-28：用户在私有核心与 MCP 合仓、以及核心/DSH/MCP 三仓之间选择三仓。共享核心由私有核心仓库维护，DSH 继续使用现有公开 MoneyPal 仓库，MCP 保持独立私有产品仓库；接受核心构建包与两个产品引用的跨仓协调成本，后续通过明确接口与自动化减少日常步骤。

DSH 保留现有仓库、产品身份及安装入口。DSH 与 MCP 接入共享核心后均先保留旧实现，待两端验证通过后，再以独立清理步骤移除已提取的重复代码。迁移保持两端各自已有的公开行为与契约，不顺带统一行为差异或增加新功能；沿用普通迁移提交保留历史，不重写已有提交。

## 已比较的方案

- 私有核心与 MCP 同仓、公开 DSH 另仓：核心和 MCP 可在同一提交中联调，但用户选择保留核心的独立仓库身份。
- 核心、DSH、MCP 三仓：各自维护源码与引用，核心通过明确的交付接口服务两个产品，为本次选定方案。

## 核心范围

首轮一次提取两个产品已经共同使用的账本引擎、Python bridge、交易预览与原子提交、运行时管理、账本初始化、领域类型及共同契约，保持一个核心包。

DSH 的宿主注册、确认交互、UI/RPC 和预设留在 MoneyPal；MCP 协议、CLI、批次持久化及跨调用流程、工作区来源、产品版本读取与配套交付留在 MCP。共同契约中的已有差异在产品适配处保留；DSH 已公开的包根导出继续兼容。

## 核心交付与版本

核心源码仓库私有，固定版本的核心构建包通过 npm 公开，使公开 DSH 仓库可以取得完整构建输入。两个产品在开发工作区精确锁定核心版本及锁文件中的完整性信息。产品构建时装入核心，最终产品包维持自包含，不增加 npm 运行时依赖。公开构建包包含运行所需的 JavaScript、类型声明与 Python bridge，不将仓库私有等同于运行文件不可读取。

核心使用独立版本，DSH 与 MCP 各自固定明确的核心版本，普通更新按各自节奏接入和发布。涉及金额正确性或写入安全的修复须跟踪两个产品完成接入和交付，不能以核心已修复替代产品交付结果。

## 产物处理

公开核心包沿用当前 MCP 的轻度处理原则：压缩 JavaScript 并移除 source map，保留所需声明文件；Python 保留可执行脚本与现有布局，并检查语义一致性。验收使用处理后的实际核心包，不以源码构建通过替代安装产物检查。处理不承担实现保密承诺。

历史 core 的处理脚本仅作参考，不自动恢复其 Python 重写依赖或其他旧方案要求。核心在构建包中处理一次，产品装配保留其文件和资源布局，避免重复处理改变已验收输入。

## 迁移与验收里程碑

先完成本地迁移验收：使用固定版本和摘要的核心候选包，将其装入两个产品的实际安装包，验证既有行为、确认与取消、原子写入、结果不确定处理，以及必要的新旧包跨进程兼容；保存可复核报告。DSH 当前 release-acceptance 入口只生成 blocked 待办，不能作为实际安装包或宿主验证通过的证据。

公开核心包发布、公开来源下的完整构建、既有跨平台 CI、真实宿主验收与产品发布作为后续阶段。未运行的项目明确标为待办；核心包公开可用并完成对应验证之前，不把公开 MoneyPal 默认分支切换到无法取得的核心引用。已验证候选的版本与摘要必须可追溯，不静默改用不同核心产物。

## 旧实现保留与清理

用户补充要求：两端接入后先不移除旧实现，等验证没有问题后再移除。接入与删除必须分开：先完成共享核心接入，保留旧源码及必要的对照验证能力；验证通过并记录结论后再清理。保留期内正常产品路径只使用共享核心，旧实现作为对照与显式回退依据，不引入新旧双写或失败自动回退。验收应证明运行的是共享核心，不能依赖旧路径得出迁移通过结论。

本地迁移验收里程碑不自动触发删除。实施规格须单列清理门槛，列明两端实际安装包、公开行为、关键写入保护及适用的 CI/宿主检查。只有两端清理所需检查均通过、发现的问题已关闭、报告可复核时才删除；必需检查未完成则继续保留。具体命令与报告位置由后续规格核实并固定，不以单端通过或固定观察天数替代验证。

删除旧实现与临时对照代码后，重新构建并复验两个实际产品包，检查不存在对旧源码或资源的隐式依赖。回退以可追溯的产品改动或已验证产物为依据，不回滚账本数据，不自动重试结果不确定的写入。

## 后续规格需要核实的工程输入

- 以当前两个产品为行为基线，核对历史 moneypal-core 的可复用部分，不直接采用旧实现或旧版本作为新迁移基线。
- 核实公开 npm 包名、scope 和首次版本的可用性；保留两个产品各自的最低 Node 版本、运行时与存储协议要求。
- 在实施规格中固定生成目录、导入方式、资源装配、测试归属与实际验收命令，不把这些选择交给实施阶段临场决定。
- 固定旧实现保留清单与独立对照方式、共享核心调用证明、清理前置条件、删除清单与删除后复验命令。

本决定重新安排 MCP ADR-0010 中暂时复制核心的源码维护方式，不自动恢复旧 ADR-0008 的全部实施要求。本阶段只形成决定与文档，尚未迁移、构建验证或发布。
