# MCP 与 MoneyPal 启动检查

首次引导需要准备环境，或工具不可用时读取本文件。助手完成可执行且已授权的操作；每阶段简述目的、实际结果和下一步。只展示当前阶段需要的动作，不一次倾倒全部安装命令。

## 选择起点与授权

| 当前证据 | 从哪里继续 |
| --- | --- |
| MoneyPal 工具可调用，首次引导尚未验收 | 直接做第 4 节的账户查询与账本校验 |
| 工具发现后仍不可用 | 第 1 节检查命令，再补齐运行时、账本与宿主连接 |
| `runtime_unavailable` | 第 2 节；修复后复验并继续原操作 |
| `invalid_workspace` | 第 3 节确认当前任务根工作区，并在工具调用中传入 |
| `invalid_ledger_layout` | 第 3 节判断新账本还是已有布局问题 |

- 账本工作区默认是当前 Agent 任务的根工作区，路径指向包含 `default/` 的目录，不是 `default/` 本身。无法从宿主取得任务根目录时才请用户明确提供绝对路径；不要猜测个人账本目录，也不要使用 MCP 进程工作目录兜底。
- 全局安装、创建运行时、初始化账本或修改宿主配置前，说明具体命令或配置变更、目标位置和影响；缺少相应授权时再请求授权。新连接器不设置 `MONEYPAL_LEDGER_WORKSPACE`；已有旧配置保持原样用于兼容。启动准备的授权不替代交易预览后的确认。
- 没有命令执行或配置编辑能力时，给出当前这一步可复制的命令或配置及验收方式，等待用户提供结果后继续；不声称已经执行。重启宿主等需要用户完成的动作，说明完成后如何回到对话继续。

## 1. 检查记账工具

目的：确认宿主能够启动 MoneyPal 的 MCP 服务。

1. 工具已可调用时跳过命令检查。否则，POSIX 使用 `command -v mcp-moneypal`，PowerShell 使用 `Get-Command mcp-moneypal -ErrorAction SilentlyContinue`。
2. 命令已存在时不重装；检查已有宿主配置与报错，继续后续缺失阶段。命令存在不等于宿主已连接，终端与宿主的 PATH 也可能不同。
3. 命令不存在时检查 `node --version` 和 `npm --version`。需要 Node.js 22.18+ 与 npm；缺失或 Node.js 版本过低时说明阻塞原因，等待用户准备符合要求的环境，不擅自安装或替换其 Node.js 发行方式。
4. 前置条件满足且全局安装已获授权时执行 `npm install -g mcp-moneypal`，再检查命令是否可用。权限失败时说明用户级 npm prefix 或 Node 版本管理器的修复方向，不使用 `sudo npm`。

完成标准：确认安装命令可被找到；接下来检查运行时，最终以宿主工具调用验收连接。

## 2. 准备运行时

目的：让 MoneyPal 能够计算并校验账本。

1. 检查宿主是否配置了 `MONEYPAL_PYTHON`，在与宿主一致的解释器选择环境下执行 `mcp-moneypal runtime-status`；成功的财务调用已有运行时可用证据时跳过重复准备。
2. 状态中的 `available`、`compatible` 都为 `true` 时直接继续。仅命令退出成功不能代替状态检查。
3. 已配置 `MONEYPAL_PYTHON` 时，它必须是可执行 Python 的绝对路径。外部运行时需要 Python 3.11+、Beancount 3.2.3+、beanquery 0.2.0+；根据状态说明缺失项，由用户修复外部环境。保留该配置，`setup-runtime` 不负责修改外部解释器。
4. 使用托管运行时且尚未就绪时，说明将创建共享 Python 环境并下载依赖，需要 Python 3.11+、`venv`、`pip` 及依赖下载能力。在授权范围内执行 `mcp-moneypal setup-runtime`，随后重新检查 `runtime-status`。缺少引导 Python 或依赖下载失败时按实际错误处理。

完成标准：运行时状态可用且兼容。若尚无账本或连接，继续第 3、4 节；最终仍须通过宿主工具验收。

## 3. 准备账本

目的：确定账本保存位置，为新账本建立初始结构。

1. 取得当前任务的根工作区；无法取得时让用户明确提供绝对目录。只读检查该工作区的 `default/` 是否存在。
2. 用户选择新建且 `default/` 不存在时，说明将创建以下内容，再在相应授权范围内以该任务根工作区为命令工作目录执行 `mcp-moneypal init`。执行能力不能指定工作目录时，改为显式传入已确认的绝对路径；不要在 MCP 进程目录或插件工作区初始化。
   - `default/main.beancount`、`default/accounts.beancount`、`default/transactions/<当前年度>.beancount`；年度由命令运行机器的本地年份决定。
   - CNY 商品，以及 `Assets:C-现金`、`Liabilities:C-信用卡`、`Equity:C-期初余额`、`Expenses:C-餐饮`、`Income:C-工资` 起始账户，不含交易或期初金额。
3. 已有 `default/` 时复用账本，不执行初始化。布局需要 `main.beancount`、`accounts.beancount`、年度交易文件及正确的 include；布局有误时指出缺失项，由用户维护已有账本。初始化拒绝已有目录时保留现场，不删除目录、不反复初始化。
4. 用户选择已有账本但目标不存在时，先说明路径不符，由用户纠正路径或明确改为新建，不能自动创建替代账本。

完成标准：新账本初始化成功或已有布局检查通过；由下一节工具校验确认账本是否有效。MCP 没有 `finance_initialize_ledger` 工具，初始化使用上述官方 CLI。

## 4. 连接宿主并验收

目的：让当前助手真正连接选定账本。

Qoder、QoderWork、WorkBuddy 等办公宿主优先使用连接器界面：读取 [办公 Agent 的连接器配置](connectors.md)，先准备可粘贴配置，再逐步指导用户打开入口、填写、保存和启用。完成后回到本节验收；不要只让用户自行寻找并修改配置文件。

1. 按实际宿主的配置方式补充 MoneyPal 条目，保留其他 MCP 服务。新配置只需启动命令 `mcp-moneypal`；不要主动设置 `MONEYPAL_LEDGER_WORKSPACE`。以下是通用结构示例，配置文件位置与重载方式以实际宿主为准：

   ```json
   {
     "mcpServers": {
      "moneypal": { "command": "mcp-moneypal" }
     }
   }
   ```

2. 已有正确配置时直接重载或验收；修改时只更新目标条目，保留外部 Python 和旧版账本环境变量配置。如果宿主无法解析命令，核实它的 PATH 或配置已验证的命令绝对路径，不通过反复重装解决。
3. 按宿主支持的方式重载 MCP；需要用户重启时说明如何恢复；宿主要求新对话才生效时，提供连接器指引中的进度交接说明。工具尚未可调用时停止在连接阶段。
4. 使用当前任务根工作区作为 `ledgerWorkspace` 调用 `finance_list_accounts` 与 `finance_validate_journal`，保留返回的真实账户、`serverToday` 和 `workspaceSource` 供后续教学使用。两次调用成功且校验结果无错误，才告知用户“账本已连接并通过校验”。`legacy_env` 表示旧连接方式仍生效，应提示升级；校验有错误时说明尚未就绪及需维护的内容。

完成后：首次引导返回首次查询阶段；故障恢复返回被中断的原任务。

## 失败与中断

- 同一准备命令因相同原因连续失败两次时停止重试，报告具体命令、错误、仍缺少的条件及可执行的下一步。
- 每次修复后复验受影响阶段。运行时可用但工具仍不可调用时检查宿主连接；配置或账本错误不通过重装软件、重建运行时解决。
- 用户暂停时简述已完成阶段、当前阻塞和下一步；同一对话恢复时复用证据。新对话没有进度证据时先检查当前状态，不宣称已记住历史进度。
